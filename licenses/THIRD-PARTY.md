# Third-Party Licenses

This file lists the open-source dependencies bundled into QODIQA's own
distributed artifact (the production Docker image) whose license requires
attribution to be preserved in a redistributed work — Apache License 2.0
and the BSD family. It was generated by auditing the exact production
dependency tree (`npm ls --omit=dev --all`), not the full local development
install, so it reflects what is actually shipped, not everything installed
on a contributor's machine.

**This is not legal advice.** This document is a factual inventory —
declared licenses as read directly from each package's own metadata and
license file, and obvious compatibility flags — prepared for compliance
record-keeping. It is not a substitute for review by a lawyer before public
release, and no claim here should be read as legal clearance.

## Correction — the production image DOES ship LGPL-3.0-or-later code

The earlier "zero copyleft in the distributed production image" conclusion below was **false** and is withdrawn.
Measured in the image built from the allow-list and in the lockfile:

| Package (non-dev, installed by `npm ci --omit=dev` on linux/x64 glibc) | Version | Licence | What ships |
|---|---|---|---|
| `@img/sharp-libvips-linux-x64` | 1.3.4 | **LGPL-3.0-or-later** | `lib/libvips-cpp.so.8.18.7` + `glib-2.0` — a **dynamically loaded shared library** |
| `@img/sharp-wasm32` | 0.35.5 | **Apache-2.0 AND LGPL-3.0-or-later AND MIT** | WebAssembly build of sharp + libvips (installed, not loaded on linux/x64) |
| `@img/sharp-linux-x64` | 0.35.5 | Apache-2.0 | the sharp native binding |
| `sharp` | 0.35.5 | Apache-2.0 | JS wrapper — pinned by `package.json` `overrides` |

The other platforms' `@img/sharp-libvips-*` packages (10 variants) and `@img/sharp-win32-*` are LGPL-3.0-or-later as
well, but are not installed in the linux/x64 image.

**Why it ships:** `@xenova/transformers` `require()`s `sharp` at load time; QODIQA's text-only embedding path never
calls it (Dockerfile comment). Removing it needs either `npm ci --omit=optional` (which would also drop the KMS/HSM
optional providers) or patching the eager require — a product decision, not made here.

**Compliance position for LGPL-3.0 (dynamic linking):**
- the full licence texts ship in the image: `licenses/LGPL-3.0.txt` and `licenses/GPL-3.0.txt` (LGPL-3.0 incorporates
  GPL-3.0 by reference; both copied byte-for-byte from canonical copies, sha256 `a853c2ff…` / `3972dc97…`);
- libvips is an unmodified upstream build, loaded as a separate `.so`; the user can replace it (it is a plain file in
  `node_modules/@img/sharp-libvips-linux-x64/lib/`), satisfying LGPL-3.0 §4;
- **corresponding source**: libvips 8.18.6 — https://github.com/libvips/libvips (tag `v8.18.6`); the prebuilt package's
  build recipe and the versions of every bundled library are in `@img/sharp-libvips-linux-x64/versions.json` and
  https://github.com/lovell/sharp-libvips. The distributor of the image (the operator who ships it) should keep a
  written source offer valid for three years if it does not ship source alongside — **design decision OA-IND15-4**.

Not legal advice; counsel should confirm the position before distribution.

## The condition the dev-dependency conclusion depends on (MPL-2.0 `axe-core`)

**Stated plainly, not buried:** apart from the LGPL-3.0 libvips/sharp-wasm32 binaries above, the production
dependency tree contains no copyleft-licensed package, and that result is conditional. One more copyleft dependency exists in this repository's full
local development install — **`axe-core@4.12.1`, licensed MPL-2.0**
(Mozilla Public License 2.0, a weak/file-level copyleft) — used by the
accessibility test suite (`npm run test:accessibility`). It is listed in
`package.json`'s `devDependencies`, and the production Docker build
(`Dockerfile`, `RUN npm ci --omit=dev --ignore-scripts`) excludes
`devDependencies` from the image — confirmed directly by cross-referencing
the exact `npm ls --omit=dev --all` production tree against the full
license audit, not inferred from the `devDependencies` listing alone.

**This is the condition the clean result rests on:** if a future build ever
ships `devDependencies` into a distributed artifact, or `axe-core` (or any
other MPL/GPL/LGPL/AGPL-family package) is ever moved out of
`devDependencies` into `dependencies` or `optionalDependencies`, this
conclusion no longer holds and the MPL-2.0 obligation reappears in the
distributed product. Re-run this audit if either of those things changes,
not just when `licenses/THIRD-PARTY.md` looks stale.

The directory `sdk/javascript/node_modules` is **not** covered by this document and
is **not part of the distributed product**: it is
git-ignored (`.gitignore`'s `node_modules/` pattern) and zero files from
it are tracked in git (`git ls-files` returns 0). It is a
local build artifact for the SDK package this repository contains,
never committed. [ correction: a Docker build from a working tree DID bundle them — the old
`.dockerignore` pattern was root-anchored (LIC-03). the build context is an allow-list that excludes
`sdk/` and every nested `node_modules` refuses an image
that contains them.] It was still audited directly
(328 unique packages) as part of the same session's
work — zero copyleft found — but since it is not distributed by
QODIQA itself, no attribution obligation attaches to this repository for
its contents; a consumer who installs that SDK package themselves pulls
their own dependencies fresh from the npm registry, the ordinary case every
npm package is in, not something this repository redistributes.

Four packages in the production tree had license metadata that didn't
parse as a clean SPDX identifier. Each was individually resolved by reading
the package's own bundled license file (or, for well-known standard
licenses, by direct identification) rather than left as "unknown":

| Package | Version | Metadata as declared | Resolved license | Basis |
|---|---|---|---|---|
| `flatbuffers` | 1.12.0 | `SEE LICENSE IN LICENSE.txt` | Apache-2.0 | Read `node_modules/flatbuffers/LICENSE.txt` directly |
| `tv4` | 1.3.0 | JSON array, two license objects | Public Domain / MIT (dual) | Both permissive; no action needed |
| `pako` | 1.0.11 | `(MIT AND Zlib)` | MIT and Zlib (dual, both apply) | Zlib is a standard OSI-approved permissive license |
| `png-js` | 1.1.0 | (no `license` field) | MIT | Read `node_modules/png-js/LICENSE` directly — package.json's own omission is a metadata gap, not an undeclared license |

`flatbuffers` is already counted in the Apache-2.0 attribution table above.
The other three are permissive and require no attribution beyond what
their own bundled license files already state.

## Summary

- **The distributed production image contains LGPL-3.0-or-later code** (libvips via sharp, dynamically loaded;
  `@img/sharp-wasm32`). Licence texts ship in `licenses/`; source location and the relinking position are stated at
  the top. Otherwise no copyleft — conditional on `axe-core`/MPL-2.0 staying a `devDependency` excluded by
  `npm ci --omit=dev`.
- **Models and datasets are not covered here** — see `MODEL-PROVENANCE.md` (shipped ONNX models, Apache-2.0 base
  model, training-data sources incl. CC-BY-4.0 Aegis and the research-only jailbreak_llms prompts) and
  `DATASET-LICENSES.md` (every tracked third-party corpus, what ships, what must never be published).
- **68 Apache-2.0/BSD packages** require attribution preservation; each
  package's own bundled license file satisfies that requirement at build
  time. This document itself serves as the compliance record of which
  packages those are.
- **`sdk/javascript/node_modules`** is not distributed by this repository
  (git-ignored, untracked, excluded from the image by the allow-list) — audited anyway, zero copyleft found.
- **Not legal advice** — a lawyer should review this record, and the
  Apache-2.0/BSD license texts' own preservation at build/distribution
  time, before public release.
