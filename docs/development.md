# Developer guide

For people who change QODIQA itself. To use it, start at [START-HERE.md](README.md).

## Run it

| You want | Command |
|---|---|
| a gateway with a simulated provider and disposable Redis/PostgreSQL | `npm run dev:sandbox` ([QUICKSTART](guides/quickstart.md)) |
| the development server against your own services | `npm run dev` (isolated per-boot database, see [QUICKSTART](guides/quickstart.md)) |
| the production entry point | `npm start` / `npm run start:prod` (see [configuration](configuration/reference.md)) |

## Test it

| Gate | Command | Needs |
|---|---|---|
| unit | `npm run test:unit` | nothing (PostgreSQL-gated suites skip themselves) |
| crypto, security, concurrency | `npm run test:crypto`, `test:security`, `test:concurrency` | PostgreSQL and Redis for the PG-gated parts |
| component | `npm run test:component` (runs a serial and a parallel half) | PostgreSQL and Redis |
| coverage | `npm run test:coverage` | PostgreSQL and Redis |
| acceptance | `npm run acceptance` (twice: one run checks the previous run's results) | a migrated disposable database |
| fuzzing, formal models | `npm run fuzz`, `bash scripts/formal/run-tlc.sh` | [fuzz/README.md](../fuzz/README.md), [docs/formal](formal/README.md) |

Rules that save hours:

- **Never point a test at a real database.** Tests refuse the default PostgreSQL and Redis ports outside CI. Start a throwaway PostgreSQL and Redis on non-default ports (and set `QODIQA_PG_DATABASE=` empty) and keep `QODIQA_PG_DATABASE` empty so each boot creates and drops its own database.
- **Provider keys do not belong in the gate environment.** A suite that needs a provider provisions one itself; an exported key gives the single-provider inference two providers and breaks `/sign`.
- Timing-sensitive suites can fail once under load and pass alone. Re-run a failing file with `npx jest <path> --runInBand` before calling it a regression; a failure that repeats alone is real.

## Change it

- **Add or change a route.** Register it in the router, add its schema in `src/openapi/routeScanner.js`, then regenerate: `npm run openapi:generate`, `npm run sdk:generate`, `npm run docs:api-reference`. `npm run contract:check` fails when the code, the OpenAPI document, the SDK descriptor tables and the reference disagree. New routes also need an entry in the route-guard registry (`docs/security/route-guard-registry.json`, regenerated by the script named in its header).
- **Change the protocol.** The normative text is [QODIQA-PROTOCOL.md](protocol/QODIQA-PROTOCOL.md); vectors are generated (`npm run protocol:vectors`) and verified by independent implementations. Existing vectors are never edited; a new domain tag or field needs a vector and a spec change in the same commit.
- **Add a policy type or an evaluator.** Evaluators live in `services/policy/evaluators/`; the policy set is governed (change request, review, approval, publication by different people), so test the governed path as well as the evaluator ([POLICY_LANGUAGE.md](guides/POLICY_LANGUAGE.md)).
- **Add a documentation file.** Every file under `docs/` needs a row in OWNERSHIP_MAP.md naming the code it describes (`npm run docs:ownership`); changing that code without touching the document fails `npm run docs:check`.
- **Typecheck and lint.** `npm run typecheck` must report 0 errors; `@ts-ignore` is not accepted. Published files are English.

## Where things are

`src/` gateway code (`api/` routes, `core/` domain logic, `infra/` storage and crypto, `validation/` the artifact pipeline), `services/` providers and policy, `enterprise/` optional modules (identity, DLP), `sdk/` the four SDKs, `scripts/` tooling and checks, `deploy/` compose, Kubernetes, Helm and Terraform, `docs/` documentation, `claims/` the claim registry, `fuzz/` fuzz targets. OWNERSHIP_MAP.md maps documents to code.
