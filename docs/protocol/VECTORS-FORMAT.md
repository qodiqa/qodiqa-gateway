# Test-vector and proof formats (frozen)

> **Status:** DRAFT 5 for the freeze; binding after `APPROVAL:` in `V2-FREEZE.md`.

## 1. Vector files

Existing V1 vectors (`docs/protocol/vectors/qodiqa-protocol-vectors.json`, the audit vectors under) are **never
modified**. Cases may be appended to the existing generated sections only through `scripts/protocol/gen-vectors.js` (as did for four
`verification` cases); a case never changes position or content once published.

New V2 families are separate files in `docs/protocol/vectors/`, one family per file, all generated by a script under `scripts/protocol/` from
the production implementation and re-derived by the two independent verifiers (`verify-vectors.js`, `verify_vectors.py`) with no production code:

| file | family | id pattern | content |
|---|---|---|---|
| `v2-canon.json` | JCS-P1 canonicalization | `V2-CANON-nnn` | accepted inputs → canonical bytes; one rejected input per rejection class |
| `v2-request.json` | V2 request binding | `V2-REQ-nnn` | requests → `requestHash`; query sorting, duplicates, percent-decoding, `+`, header lists, absent header, path spelling, mismatch cases |
| `v2-artifact.json` | V2 claims | `V2-ART-nnn` | `crit`, unknown claims, `v` spellings, `limits`, strict `claims` |
| `action.json` | action binding | `ACTION-nnn` | `actionHash` of valid actions; argument/ordering/replay/schema-change/cross-tenant mismatches |
| `delegation.json` | delegation chains | `DELEG-nnn` | valid chains, attenuation violations, depth, cycles, revocation |
| `audit-v8.json` | audit entries | `AUDIT-V8-nnn` | one entry per type (v7 and v8), tampered entries, the shape rules of AUDIT-V8-FREEZE section 3 (mode `verify`; input `{ entry }`; verdict `ok` or the first failing rule) |
| `audit-proof.json` | downloadable proof | `AUDIT-PROOF-nnn` | one `qodiqa-proof/1` document each: complete, every optional part absent, every check failing (mode `verify`; input `{ proof }`; expected `{ verdict, failed: [{ id, code }], partial: [...] }`) |
| `audit-anchor.json` | anchor line | `AUDIT-ANCHOR-nnn` | one line of an anchors repository each: valid statements (digest expected) and every malformed or forged line (mode `verify`; input `{ line }`; expected `{ digest }` or `expectedError.code` `ANCHOR_LINE_MALFORMED` / `ANCHOR_DIGEST_MISMATCH`) |
| `receipt.json` | signed receipt | `V2-RECEIPT-nnn` | receipts, tampered receipts, wrong key |

**Published:** `v2-canon.json`, `v2-request.json` and `receipt.json` (V2-RECEIPT-nnn, mode `verify`: a receipt and an optional `trustedAt`, expected verdict `ok` or the first failing rule; signed with published test seeds by `scripts/protocol/gen-receipt-vectors.js`, re-derived by both independent verifiers — the Python one with a pure-standard-library Ed25519 — and consumed by the conformance tests of both SDKs), generated by `scripts/protocol/gen-v2-vectors.js` from the production implementation (inputs in
`scripts/protocol/v2-vector-cases.js`) and re-derived by two independent verifiers that import nothing from `src/`: `scripts/protocol/verify-v2-vectors.js` (Node) and
`scripts/protocol/verify_v2_vectors.py` (Python standard library only, with its own ECMAScript number formatting). `INDEX.json` (generated) pins the counts. The three
implementations agree on every case; `scripts/protocol/__tests__/v2Vectors.test.js` also fuzzes production against the verifiers (1,500 canonicalization inputs and 1,500 requests per run)
and checks that an accepted value is byte-identical to the V1 canonicalizer. **Published:** `audit-v8.json` (AUDIT-V8-nnn) and `audit-proof.json` (AUDIT-PROOF-nnn), generated by `scripts/protocol/gen-audit-vectors.js` from the production writers with published test seeds and a frozen clock (`auditVectorFixture.js`), re-derived by the independent Node verifier (`scripts/audit-repro/verify/proof.js`, `auditContract.js`) and by the Python verifier (`scripts/audit-repro/verify/qodiqa_proof_verify.py --vectors`, standard library only), and checked against the production entry checks by. Mixed v7/v8 chains, lifecycle/ordering walks and downgrade stay in the chain-walk suites. The remaining families of the table are produced by the waves that introduce them.

**Bytes in `input`.** Every input is bytes so that no host-language string handling can influence it: a lower-case hex string, or `{ "repeat": { "prefix", "unit", "count", "suffix" } }`
(UTF-8 text `prefix + unit x count + suffix`, for the 64 KiB / 1 MiB / depth cases). A canonical output above 4096 bytes is pinned by `expected.length` and `expected.sha256` instead of inline hex.
`v2-request` input: `{ method, target, headers: [[name, value]…], bind: [names], body }` (bytes; `body: null` = no body at all); a refusal is `expectedError.code REQUEST_MISMATCH`, with
`detail` = the JCS-P1 code when the refusal is a canonicalization failure of a string, the body or the document.

## 2. File shape

```json
{
  "format": "qodiqa-vectors/1",
  "family": "v2-request",
  "generatedBy": "scripts/protocol/gen-v2-vectors.js",
  "specVersion": "v2-freeze-1",
  "mode": "verify",
  "nowMs": 0,
  "inputSchema": { "type": "object" },
  "keys": [ { "keyId": "…", "publicKeySpkiB64": "…", "status": "active" } ],
  "cases": [
    {
      "id": "V2-REQ-001",
      "description": "one line",
      "input": { },
      "expected": { "outcome": "ok", "value": "…" },
      "expectedError": null
    }
  ]
}
```

* Each family file declares `inputSchema` (a JSON Schema of the `input` object of its cases) and `mode` (`"compute"` — the verifier recomputes `expected.value` —
  or `"verify"` — the verifier reproduces `expected` or `expectedError`), so a verifier written from the file alone knows what to do.
* In `compute` mode a refusal (for example a request the binding of V2-FREEZE 3 refuses) is a vector with `expectedError.code` `REQUEST_MISMATCH`; a canonicalization
  rejection carries its canonicalization code (V2-FREEZE 2.7).
* A vector names exactly **one** error code: the first failing rule in the order of the normative text.
* `id` is unique and stable; a case is retired by adding `"deprecated": true` — never by removal or edit.
* `expected` and `expectedError` are mutually exclusive; `expectedError` is `{ "code": "<code>", "detail": "<optional>" }` where `code` is any of: a V1 reason
  (`REQUEST_MISMATCH`, `INVALID_SIGNATURE`, `INVALID_ARTIFACT`, … — `QODIQA-PROTOCOL.md`), a code of `V2-FREEZE.md` 1.3, a canonicalization error code
  (`V2-FREEZE.md` 2.7), or an audit verification failure (`SCHEMA_DOWNGRADE`, `COMMIT_WITHOUT_DECISION`, … — `AUDIT-V8-FREEZE.md` 4) with the
  failing `reason`/`detail` string where the verifier reports one.
* All keys in vectors are **published test seeds**, never deployment keys; the verification clock is pinned in the file (`nowMs`).
* Counts per family (and per section of the V1 file) are recorded in `docs/protocol/vectors/INDEX.json` (generated) and pinned by a test, so a
  silently shrinking family fails CI. Documents cite that file, not literal counts.

## 3. Downloadable proof (`qodiqa-proof/1`)

A proof is one JSON document a third party can verify offline with the independent verifier:

```json
{
  "format": "qodiqa-proof/1",
  "generatedAt": 0,
  "subject": { "tenantId": "…", "requestId": "…" },
  "artifact": { },
  "auditEntries": [ ],
  "transparency": { "leaf": { }, "inclusionProof": { }, "root": { } },
  "checkpoint": { },
  "anchors": [ { "kind": "git|ots|rfc3161", "receipt": "…" } ],
  "receipt": { },
  "keys": [ { "keyId": "…", "publicKeySpkiB64": "…", "status": "…", "activatedAt": 0, "retiredAt": null, "revokedAt": null } ]
}
```

Rules: every hash and signature in the document is checked with the algorithms of the protocol documents and nothing is taken from the
generating server; `keys` carries only *public* keys and the verifier can be told to take keys from the anchor repository instead
an absent optional part (`anchors`, `receipt`) lowers the verdict (`VALID_PARTIAL`), it never raises it; a
document with an unknown `format` is refused. The verdict vocabulary is `VALID`, `VALID_PARTIAL`, `INVALID` (+ a list of the failed checks).

### 3.1 Verification

`scripts/audit-repro/verify/qodiqa-proof-verify.js` (Node) and `scripts/audit-repro/verify/qodiqa_proof_verify.py` (Python) implement the rules below with no code from the gateway; the gateway does not store the artifact, so the caller supplies it (`--artifact`) or the document carries it. Exit codes: 0 `VALID`, 3 `VALID_PARTIAL`, 1 `INVALID`, 2 usage.

| check id | what is verified | failure codes |
|---|---|---|
| `FORMAT`, `SUBJECT`, `KEYS` | the document is an object of format `qodiqa-proof/1`; `subject.requestId`; `keys` is a list of `{ keyId, publicKeySpkiB64 }` | `NOT_AN_OBJECT`, `UNKNOWN_FORMAT`, `SUBJECT_MISSING`, `KEYS_MALFORMED` |
| `ARTIFACT_SHAPE`, `ARTIFACT_SIGNATURE`, `ARTIFACT_KEY_WINDOW` | exactly the five artifact keys; the signature is the canonical base64 of Ed25519 over `SHA-256("QODIQA::ARTIFACT::V1" ‖ canonical({expiry, payload, publicKeyId, timestamp}))`; the key was neither revoked at or before, nor activated after, the artifact's `timestamp` (a key revoked later still attributes the artifact) | `ARTIFACT_SHAPE`, `UNKNOWN_KEY`, `BAD_SIGNATURE`, `SIGNATURE_NOT_CANONICAL`, `KEY_REVOKED_AT_ISSUE`, `KEY_NOT_YET_ACTIVE` |
| `ENTRY_HASH:<n>`, `ENTRY_REQUEST` | every entry of `auditEntries` has its canonical form, hash and shape (schema versions 1-8); every entry belongs to `subject.requestId` | the codes of `audit-v8.json`, `ENTRY_REQUEST_MISMATCH`, `AUDIT_ENTRIES_MISSING` |
| `ENTRY_SIGNATURE_BINDING`, `ENTRY_REQUEST_HASH`, `ISSUED_AT_MISMATCH` | with the artifact: entries whose `signature` is not `UNAVAILABLE`/`SYSTEM` carry the artifact's signature; their `requestHash` is the artifact's; a v8 entry's `issuedAt` is the artifact's `timestamp` | `ENTRY_SIGNATURE_MISMATCH`, `REQUEST_HASH_MISMATCH`, `ISSUED_AT_MISMATCH` |
| `LIFECYCLE` | INTENT / STREAM_OPENED, then exactly one DECISION, then COMMIT | `LIFECYCLE_ORDER`, `NO_DECISION`, `TWO_DECISIONS`, `COMMIT_WITHOUT_DECISION` |
| `TRANSPARENCY`, `TRANSPARENCY_BINDING` | the leaf's entry hash, signature, the RFC 6962 inclusion path at the stated position of the tree the signed root covers; the leaf documents one of the request's entries with the same decision and request id | `TRANSPARENCY_INVALID`, `LEAF_DOES_NOT_DOCUMENT_ENTRY` |
| `CHECKPOINT`, `CHAIN_PATH` | the signed checkpoint (`QODIQA::AUDIT_CHECKPOINT::V1`, key from `keys`, never a revoked one); `chainPath` is the contiguous chain from the request's first entry to the checkpoint head: every entry sound, every `prevHash` the previous hash, the last hash the head, every entry of the request inside it | `CHECKPOINT_*`, `PATH_ENTRY_*`, `PATH_BROKEN_LINK`, `PATH_DOES_NOT_REACH_HEAD`, `ENTRY_NOT_IN_PATH`, `CHECKPOINT_NOT_VERIFIED` |
| `RECEIPT`, `RECEIPT_BINDING` | the signed receipt (V2-FREEZE 6) verifies and names this request, the DECISION's decision and hash | the receipt codes, `RECEIPT_MISMATCH:<fields>` |
| `ANCHORS` | each anchor has a known `kind` (`git`, `ots`, `rfc3161`) and a receipt text | `ANCHOR_MALFORMED` |

The verdict is `INVALID` when any check fails. Otherwise it is `VALID_PARTIAL` when something optional is absent or not evaluated, and the reasons are listed in `partial`: `ARTIFACT_ABSENT`, `TRANSPARENCY_ABSENT`, `CHECKPOINT_ABSENT`, `CHAIN_NOT_ANCHORED` (a checkpoint without a chain path: the entries are self-consistent but not tied to the signed head), `RECEIPT_ABSENT`, `ANCHORS_ABSENT` and `ANCHORS_NOT_EVALUATED`. **Without an anchors repository no proof is `VALID`**: the best verdict is `VALID_PARTIAL` with `ANCHORS_NOT_EVALUATED` (nothing independent of the gateway says the checkpoint existed). With `--anchors-repo <dir>` the verifier takes the checkpoint keys and the checkpoints from that git working tree (`anchors/<date>.jsonl` statements `{ digest, statement }`, `keys/checkpoint-keys.json`, `keys/transparency-keys.json`; format and finding codes in `scripts/audit-repro/verify/anchorTrust.js`): the repository must be clean, append-only in history (`--require-signed` also demands valid git signatures), with monotonic fork-free anchors; the proof's checkpoint must verify under the **anchored** keys and be an anchored statement — or an anchored head must lie on the chain path at or after every request entry (`CHECKPOINT_NOT_COVERED_BY_ANCHOR` otherwise, a partial); a checkpoint for an anchored position with a different head is `CHECKPOINT_FORKS_ANCHOR`, a proof key that differs from the anchored one `PROOF_KEY_DIFFERS_FROM_ANCHORED`. OpenTimestamps / RFC 3161 receipts are listed as `ANCHOR_RECEIPT_NOT_EVALUATED:<kind>`. A part can lower the verdict, never raise it.

### 3.2 Anchor lines

The anchors repository written by the gateway's git anchor (`docs/configuration/reference.md` section 20) holds `anchors/<UTC date>.jsonl`, one line per anchored checkpoint: `{ "digest", "statement" }`. The **statement** has exactly the keys `v` (1), `checkpointId`, `payloadHash` and `headHash` (64 lowercase hex), `chainLength` (a positive integer not above 2^53 - 1) and `createdAt` (text); the **digest** is `hex(SHA-256("QODIQA::EXTERNAL_ANCHOR::V1" || canonical(statement)))` with the sorted-key compact JSON canonical form. A line with another shape is `ANCHOR_LINE_MALFORMED`, a line whose digest is not its statement's is `ANCHOR_DIGEST_MISMATCH`; `audit-anchor.json` pins both, and the JavaScript SDK (`checkAnchorLine`), the Python SDK (`check_anchor_line`), the independent Node verifier and the pure-Python verifier give the same verdict for every case.
